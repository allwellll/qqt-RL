# 四 Bot × 64 局统一快速评估（2026-10-01）

## 协议

- 14 个 checkpoint；每个 checkpoint 分别对战 4 个 Bot，各 64 局，共 3,584 局。
- 固定 seed `20261001`、相同出生清单、actor=P0、greedy、`max_steps=300`、`danger_arena=1`，清除可破坏砖块。
- Tactical v2：JAX 环境 + Python `bun.tactical_v2`，模型在 GPU 推理。
- 猎手三档：真实 `web/sim.js` + `web/bun_hunter_bot.js` + `web/bot_contract.js`，模型使用 Web `TransformerModel`，分别运行 hard/normal/easy。
- Web 与 JAX 的初始观测、全局状态和移动 mask 已做 parity 检查；但 Tactical 与 Web 猎手仍是不同模拟器/对手协议，结果只能在同一 Bot 列内比较，不能把不同列当作相同难度。
- 指标顺序：存活非换命击杀% / 被 Bot 击杀% / 自炸% / 换命% / W-L（局数）/ 模型场均放泡。
- 64 局仅用于快速筛点，单个事件约 1.56 个百分点；不得替代既有 1024 局确认，也不能单独支持晋升。

## 结论

1. 历史 it4000 与 Reward V2 long it200 的 Tactical v2 存活击杀均为 43.8%，是本次点估计最高；Reward V2 long 更激进（29.9 泡/局），但64局不足以判定优于历史点。
2. dp8 的训练 Bot 专项收益没有迁移到 Tactical/Web 猎手：it8000、it12000 对 Tactical 明显回退，且猎手三档自炸/失败较高；维持“不晋升”。
3. 场景 scenario 两个 seed 都显著压低自炸，尤其 s1 final，但对猎手困难/普通几乎没有存活击杀，并伴随放泡下降，属于安全但保守的攻击塌缩；不晋升、不启动当前配置长训。
4. 网页猎手困难/普通下多数 checkpoint 的存活击杀接近零，说明这是当前共同短板；下一轮应同时保持 native 进攻能力并降低 scenario 占比，而不是单纯延长训练。
