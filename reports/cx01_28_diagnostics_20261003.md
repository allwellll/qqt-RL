# CX-01 至 CX-28 机制诊断与复现记录

日期：2026-10-03

本报告保存影响后续实验设计的诊断和失败原因。逐轮假设、唯一变量、真实四 Bot 结果和晋升决定见[实验总账](../docs/training_experiment_ledger.md)与[精炼经验索引](../docs/cx_experiment_lessons.md)；CX-29 的独立确认和长训判断见[专项报告](cx29_trap_routes_20261003.md)。这里的 `runs/` 路径仅为原始证据定位，不是 Git 追踪的产物。

## 证据口径

统一快筛每个模型对 Tactical v2、真实 JS hunter hard/normal/easy 各 64 局，固定 seed 20261001、同出生、greedy、300 tick。它只筛选检查点。确认使用独立评估 seed，每模型每 Bot 512 局、同出生配对、10,000 次 paired bootstrap；原候选与独立训练 seed 均须满足综合 C、逐格 surviving-kill 和放泡门槛。文中的 S 是存活且非换命击杀，T 是换命，D 是自炸，B 是每局放泡数。Tactical 与网页猎手来自不同模拟器，只在同一 Bot 列内比较。

## 信用、奖励与梯度

| 证据 | 观察与设计影响 |
|---|---|
| CX-01 至 CX-06 | lambda `.99`、删除安全结算、临爆 pressure、隔离 value 梯度各自的 64 局快筛均为 0/24。CX-05 后期四格自炸增加；CX-06 虽由只读梯度审计提出，但隔离后攻击不足。因此单靠延长信用、减少奖励或分离梯度，没有形成网页攻击转化。 |
| CX-04 采样诊断 | 新训练轨迹中，top25% 选中集合的平均绝对优势为 1.5391，均匀集合为 .5928；死亡等待帧确实进入 PPO，但 topk 选中死亡帧仅约 .5% 至 .8%，其优势权重不足 .8%。这不支持把退化主要归因为死亡帧；CX-04 两臂 0/24 也不支持直接改成均匀采样。 |
| CX-09 奖励分解 | 冻结 self-play 下，两条 CX-09 final 的 placement+resolution+threat 奖励合计约 10,286/9,444，存活击杀奖励仅 108/216。它提示塑形量级可能淹没击杀，但轨迹是描述性关联，不能当作训练失败的因果证明。CX-10/11 的塑形调整在独立重训未通过确认。 |
| CX-20、CX-22、CX-23 | 增加终局击杀奖励或改变 EMA 能得到正的原点综合 C，部分独立重训 C 也为正；但 Tactical 下界分别到 -.0586、约 -.0996、-.0625，CX-22 hard trade 达 18。停止单向奖励加码，不能用放泡或 easy 收益覆盖保底失败。 |
| CX-25 标签边界 | HL-Gauss 支持 `[-20,20]` 的合成标签 48 曾出现近零 loss/梯度；真实四批 131,072 个 GAE return 仅 8 个标签质量低于 .5，不能称为既有退化主因。边界投影在两次 512 局确认中使综合 C 数值门槛通过，但 hard S 均 0/512，保留这一限制。 |

## 对手与网页机制

| 证据 | 观察与设计影响 |
|---|---|
| CX-07/08/09 | 50% JAX hard 或单独清砖都未产生快筛候选；清砖降低自炸同时使 Tactical 放泡和攻击下降。清砖加对手比例 CX-09 原点通过、独立训练 seed 未复现。几何和对手改变应拆开验证，安全与击杀必须同时守住。 |
| CX-12 对手分组诊断 | 三模型的 hunter actor 入选比例约 58.95%/43.85%/46.42%；有偏差，但并非严重漏采。GAE return 未超出当时价值头支持范围。该小样本只读诊断不足以断定组别采样是 Tactical 退化根因，CX-26 的等配额实测也未通过原点保底门槛。 |
| 真实 JS hunter 机制 | 每模型、每档 16 局的只读诊断中，hard 相邻格假想泡额外缩减安全动作约 3.03%/3.17%/5.96% 的双方存活 tick；trapSearch 返回非直线攻击目标占 29.08%/25.45%/41.27%。normal 对应机制计数为零。JAX `hunter_hard` 缺少这些行为，故 JAX 对战不能替代真实网页四 Bot；机制频率不证明其造成全部失败。 |
| CX-16/24/27/28 | 相邻格预判、学习型对手 greedy 解码、强 reference、JAX 逃路缩减奖励均未在独立确认中带来 hard 安全击杀。CX-27 的 hard 瞬时 threat 泡增加而实际击杀仍为 0；CX-28 全 16 个 64 局保存点 hard S 均为 0。瞬时威胁与逃路近似不能代替真正结算。 |

## 复现与运行协议

CX-09 至 CX-24 中多次出现原点 512 局综合分通过、独立训练 seed 的 Tactical 或综合分失败。CX-13 原点 Delta C +.365，重训 -1.055 且四 Bot 自炸激增；CX-19 原点 +.197，重训 -.107；CX-24 原点 +.141，重训 -.260，hard/normal 自炸 97/79（基线 17/25）。固定候选与独立 seed 不能在看到结果后改选；64 局快筛的通过点绝非晋升证据。CX-25 是数值收益可复现的受限例外，其 hard 主动击杀仍无改善。

- CX-01 首次正式训练因外部 SIGTERM 中断，旧状态仍写 running；以实际进程退出和 checkpoint 完整性判定，新 namespace 从相同初始化重跑，不混合残缺缓存，也不把 SIGTERM 归因为数值发散。
- CX-05 快筛因 checkpoint 距启动不足 60 秒被评测器拒绝；保留失败记录，仅恢复缺失单元，不把评测启动保护误判为训练失败。
- CX-14 的同 seed 回放与历史参数 75/75 leaf 不同；现有审计未隔离底层数值、编译或硬件因素，不能据此指定单一根因，也不能把同 seed 当成逐位复现保证。
- CX-24、CX-25 的首次定向测试失败来自测试替身 ability 维数或 float32 严格比较，修正 fixture 后完整回归通过；失败尝试和测试输出仍应保留。CX-26 的 PPO 包装曾漏传 safety/reference 参数，正式训练前用 smoke 与接口测试补齐。
- CX-28 独立重训首次误从筛选权重初始化、第二次准备时历史路径错误；两次均标为无效，最终有效 run 从历史 it4000 SHA 初始化。来源 SHA、实际更新数、EMA/raw 索引、训练 seed、评估 seed、同出生和真实 JS 来源都应逐项审计。
