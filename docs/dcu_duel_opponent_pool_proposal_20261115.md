# 对拼后期退化与强历史对手池建议（2026-11-15）

本页回答本次用户关于“后期越训越差，是否增加强版本自对弈”的问题。
这是下一轮对拼训练的建议，**没有在本次实现对手池或启动击杀训练**。
本次每卡 2048 的默认值调整针对已实测的运包两阶段入口，不直接改旧击杀采样器的批次。

## 已证实的现象

[同协议复核](dcu_convergence_and_latest_20261115.md)每点 48 局：u930 为 45 胜 / 1 平 / 2 负，
u1030 为 19 胜 / 18 平 / 11 负；自死次数从 11 次升至 258 次。
训练末段 K/D 却从约 3.64 升至 4.28，Critic loss 与熵没有明显发散。
这说明固定评测确有退化，混合训练指标不能替代它；尚未确认是哪一种机制导致。
48 局复用了选型种子，且部分评测对手参与训练，不能当作独立测试集成绩。

## 旧实现的局限与可能原因

旧 `jax_kill_collect.py` 默认规则 bot 占 50%、当前快照 25%、上一份历史快照 12.5%、
SP/G 各 6.25%。历史槽只有一份，在整局结束时用上一份 current 替换，
不是保留多个经过评测的强版本。弱版也可能随后覆盖 current/history。

- **对手分布漂移与遗忘**：模型可能适应最近对手，遗忘旧对手或只学会互相克制的循环策略。
  多个强版本长期留池，能缓解这类问题。
- **规则 bot 占比过高**：继续利用易预测 bot 的收益，可能与对强模型的进步脱节。
  需要按对手类别拆分指标，不能只看合计 K/D。
- **优化引起的策略退化**：PPO clipping 和梯度裁剪不能保证完整局能力单调提升。
  平均 loss 平稳不能排除少数危险状态动作变坏；应监控更新前后 KL、概率比、梯度和分组自死。
  现有数据不足以认定是学习率过大或 Critic 发散。
- **训练与评测条件差异**：训练采样与温度 0.3 的评测不同，训练 JAX 适配器与网页计分归因
  也有已记录差异。它们不能抹掉同协议下的版本退步，但可能解释为何训练统计与网页表现脱节。
- **数值或实现问题**：旧击杀入口只有有限值等检查，没有新版运包入口的 logp/value 重推理门禁。
  下一轮应独立检查真实模型在目标批次上的概率一致性，不能把新运包采样器通过当作旧击杀也通过。

## 建议的下一轮配置

从 u930 起步，而不是直接继续退化的 u1030。建议先用以下比例做小规模验收，再按评测调整：

| 对手来源 | 环境占比 | 用法 |
|---|---:|---|
| 多个强历史版本 | 70% | u930、u840 和其他经同协议验证的版本；保留约 4–8 个有差异的模型 |
| 最近合格版本 | 10% | 冻结快照，经评测合格才更新，不无条件采用最新训练权重 |
| 外部 SP/G 模型 | 10% | 各 5%，保留不同风格的固定锚点 |
| 规则 bot | 10% | 保留基础行为覆盖，避免完全遗忘 |

自身历史模型合计 80%，所有对手整局冻结；每局随机抽样，双方席位平衡。
“自对弈”不要求双方同时更新梯度；被训练方更新，对手使用冻结快照就可以。
不能只堆多个很相似的版本，模型数量多不等于策略多样。

历史池内保留最低抽样概率，再适当偏向当前胜率约 30%–70% 的对手，
避免只打最弱或最强一个版本。胜率依据完整局结果，不能用击杀率代替。
这个比例和范围是建议起点，尚未训练验证，不是已经生效的参数。

## 比单纯提高比例更关键的保障

1. 保留固定评测对手与种子做趋势监测，另留未用于晋级的对手或种子作最终验收。
   每约 10–15 分钟评测候选，先用较小样本筛选，接近或存在退化疑点时扩大双席位局数。
2. 依据完整局胜率、净击杀和自死等指标综合晋级，不能默认“新版本更强”。
   只发布通过评测的候选到对手池，原 best 与最新点分开保存。
3. 若固定锚点明显退步或自死骤增，先暂停晋级、检查录像与分布；必要时从 best 新开一轮，
   按需要降低 Actor 学习率或增加 KL 约束。不能把丢弃优化器的重启说成精确回滚。
4. 正式开训前核对 JAX/网页规则、动作掩码和 BF16 采样重算，并对比训练/部署温度下的行为。

强历史池主要处理对手分布和遗忘；评测晋级防止弱版本污染池。
如果根因是数值、规则或奖励归因，增加自对弈比例本身不能修复它。
