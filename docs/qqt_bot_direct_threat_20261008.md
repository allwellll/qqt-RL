## 根因与最小实现

原 Coop 单人模式不采样敌人运动；原攻击评分以当前 floor 格、乐观逃生比例和短运动路线为主，错峰 usefulness 的几何覆盖不能证明 native 完整身体命中。新的 hard 攻击先观察已发生的运动，使用实际引信/连锁 tick、逐来源射线和真实 Sim `_steer` / `_isHitByExplosion` 检查当前泡能否在目标继续当前运动时新增命中。当前目标在射线外也能主动放泡；明确安全的直接威胁高于无目标 OPEN_ROUTE。

每个证明包括目标、观察来源、预测动作/路径、baseline 路径、候选来源 cell、预测命中及爆炸 tick、射线和安全常量动作。`conditional-hit` / `guaranteed:false` 明确表示条件性承诺；五个常量动作不是完整时空可达域，不宣称必杀。目标改道后，有限追击窗口选择完整覆盖预测身体的放泡点，并拒绝没有新增真实威胁的旧 reserve/chain/擦边攻击。后续泡可以与第一枚共存，在不同 tick 爆炸。

预测仅统计爆炸本 tick 的 impact，不拼余焰；需候选泡自身完整覆盖身体，不把其他来源补齐半身的 union 或旧泡先命中冒认为此泡命中。墙、砖、泡阻挡和实际提前连锁均纳入。香蕉、预测期内状态失效、活动推箱、起点/扫掠路径道具或宝箱返回不确定，回退原安全策略；不宣称精确预测这些复杂变化。已知长期慢慢胶按实际速度预测。

原泡上限 hard=4、自然放置后引信30（相对决策31）、3 tick保险、hypoSurvivors、连续物理撤离和队友空间/静止/搬包路线保护均保留；直接攻击 solo 也必须通过连续撤离及提前3 tick保险。救援、搬包和道具任务不被抢占。没有读取未来玩家输入。

## TDD 与真实 Sim 口径

证据根目录：`runs/qqt_direct_threat_20261008/`。`tdd-behavior-red.log` 是内存 Git 基线真实动作 route 而非 bomb_direct 的行为 RED；`tdd-open-route-red.log` 验证攻击优先级缺口；`tdd-two-capacity-red.log` 复现两泡容量追击只擦半身而未命中；`tdd-departing-item-red.log` 复现离开道具起点时漏检；`tdd-source-attribution-red.log` 通过仅移除来源保险的内存模块复现跨来源误归因，不覆盖工作树。早期失败和被拒绝的探索产物保留，最终只以本报告列出的 comparison/日志为准。

`web/test_bot_direct_threat.js` 覆盖射线外预判、同线无出口且玩家持续求出口的实际捕获、第一枚改道/第二枚共存错峰完整命中、硬墙/软砖/射程、无敌、半身及跨来源覆盖、香蕉/胶失效/道具保守回退、长期慢胶、提前连锁正反例、自困/对方临爆泡、静止队友/救援/搬包拒绝和确定性回放。旧 Coop、STAGGER、oracle 套件继续验证临爆补泡、分区开墙、搬包拦截和救援。

`eval_direct_threat.js` 为双方使用同一个只读目标 oracle，基线通过 git show 内存加载，避免因旧版没有 metadata 而虚报零威胁。命中需本泡完整身体覆盖及实际 native damage/capture；改道需可见泡使当前路径失效，并绑定 threateningSources。每泡保存实际放置、爆炸、natural/chain父来源、预测/实际目标路径、撤离路径和判伤余量。目标响应器仅依据当下可见炸弹选安全动作，攻击方不知道其未来输入。
