# 方向控制、大鸟空投与死亡掉落验证（20261005）

## 基线与复现

- worktree：`cx_bot_cooperation_20261004`，基于最新 main `9e26908`；没有修改其他开发 worktree。
- 旧控制使用固定上/下/左/右优先级。真实 Chromium 加载旧 `controls.js` 后，按住上再按左仍返回上，横坐标不变。
- 旧渲染器没有飞鸟绘制；模拟器虽有墓地道具回收，但每 tick 至多投一个，剩余队列在周期末随机补落，表现为凭空出现。
- 旧 `_killPlayer` 不清空道具栏：带香蕉 2、慢慢胶 6 调用死亡后仍全部持有。

## 实现

- 方向取 Set 中最后加入、仍按住的箭头键；浏览器重复 keydown 不改变顺序。释放最新键回退前一个，blur 清空按键和待放道具/泡泡。
- 从官方 v1.3.2 发行包导出 `object/misc/misc101_stand.img`，使用六帧原版大鸟位图。
- 网页原生规则仍每 300 tick 回收一次道具。周期 270..299 tick 从右向左飞行，沿当前列分批投放，落地前有 3 tick 的下落过程且不能拾取。大量道具可以同 tick 投多个；没有合法落点时保留到下一轮，不随机瞬移补落。飞行位置由模拟器提供，渲染不消耗 RNG。
- 真正死亡时清空香蕉/慢慢胶全部库存，恢复开局属性，掉落获得的泡数、威力、速度增量。被糖泡困住、被救出不掉落；初始角色属性不掉落。
- 同类掉落以带数量的拾取物保存，画面显示数量；拾取慢慢胶保留实际库存数量，普通地图慢慢胶仍一次给 3 个。落点避开墙、砖、房屋遮挡、泡泡、火区、已有道具、空投预留格和活角色；无落点时保留待落队列。
- 掉落道具再次被炸毁时，其种类与数量进入大鸟回收队列。快照保存数量、飞行投放、下落与待落队列，兼容旧快照缺省字段。
- 训练/模型默认模拟路径保留旧规则。本轮没有改 bot 算法。
